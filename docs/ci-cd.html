    CI / CDCI / CD

    The GitHub workflows of libutils: lint, unit tests (with ASan), packages, pre-releases and GitHub releases, publication on gh-pages and the downstream notification.Les workflows GitHub de libutils : lint, tests unitaires (avec ASan), paquets, pré-versions et releases GitHub, publication sur gh-pages et notification en aval.

    Updated 2026-11-27

    The workflows of .github/workflows/ test, build and publish the library on each push. The local commands are on Build, tests and hooks.

    Les workflows de .github/workflows/ testent, compilent et publient la bibliothèque à chaque push. Les commandes locales sont sur Build, tests et hooks.

    1. WorkflowsWorkflows

    WorkflowRole
    Dispatch (CI/CD)Runs on every push (branch main or tag v*, not for *.md / *.txt / docs/ only changes) and decides what to trigger from the ref / commit message; waits for the triggered workflows and fails with them
    Lint (CI)On every push of main (not with [ignore]): shellcheck on the shell scripts and the hook, actionlint on the workflows, xstyle on the whole repository (a major issue fails, include/utils/algorithms excluded like the hook); a tool that cannot be installed is only a warning
    Unit Tests - Libraries (CI)Builds and runs the unit tests (ctest, in parallel), always first: Linux in the unit-tests image (Debug, then the same tests with the AddressSanitizer), Windows (build-unit-tests-windows) built with MinGW-w64 and run with wine in the mingw64-unit-tests image (a test that hangs on exit is retried once)
    Build - Packages (CI/CD)Builds the packages (RPM / DEB / Arch in the ci image, mingw64-libutils* in the build-packages-windows job on mingw64-ci), signs them and publishes them on gh-pages; the publication waits for both jobs, a tag whose version is not project(... VERSION) is refused
    Release - GitHub (CD)On a v* tag, once its packages are published: the GitHub release (a pre-release for a -pre tag), its notes = the section of the tag in CHANGELOG.md ([pre-release] for a -pre tag without its own), the RPM / DEB / Arch packages attached
    Docs - Pages (CD)On a push of main changing docs/: copies the built pages (not the sources docs/site/) on gh-pages
    Build - Libraries (CI)Only builds the 3 libraries and checks they exist, when Dispatch decides not to build the packages

    Important. Every build depends on the result of the unit tests: if one fails, the pipeline stops.

    Tip. A commit containing [ignore] (preferably in its description) skips the whole CI.

    WorkflowRôle
    Dispatch (CI/CD)Tourne à chaque push (branche main ou tag v*, pas pour des changements uniquement sur des *.md / *.txt / docs/) et décide quoi déclencher selon la ref / le message de commit ; attend les workflows déclenchés et échoue avec eux
    Lint (CI)À chaque push sur main (pas avec [ignore]) : shellcheck sur les scripts shell et le hook, actionlint sur les workflows, xstyle sur tout le dépôt (un problème major échoue, include/utils/algorithms exclu comme dans le hook) ; un outil qui ne s'installe pas n'est qu'un avertissement
    Unit Tests - Libraries (CI)Compile et lance les tests unitaires (ctest, en parallèle), toujours en premier : Linux dans l'image unit-tests (Debug, puis les mêmes tests avec l'AddressSanitizer), Windows (build-unit-tests-windows) compilé avec MinGW-w64 et lancé avec wine dans l'image mingw64-unit-tests (un test bloqué à la sortie est relancé une fois)
    Build - Packages (CI/CD)Compile les paquets (RPM / DEB / Arch dans l'image ci, mingw64-libutils* dans le job build-packages-windows sur mingw64-ci), les signe et les publie sur gh-pages ; la publication attend les deux jobs, un tag dont la version n'est pas project(... VERSION) est refusé
    Release - GitHub (CD)Sur un tag v*, une fois ses paquets publiés : la release GitHub (une pré-version pour un tag -pre), ses notes = la section du tag dans CHANGELOG.md ([pre-release] pour un tag -pre sans la sienne), les paquets RPM / DEB / Arch attachés
    Docs - Pages (CD)Sur un push de main qui change docs/ : copie les pages construites (pas les sources docs/site/) sur gh-pages
    Build - Libraries (CI)Compile seulement les 3 bibliothèques et vérifie qu'elles existent, quand Dispatch décide de ne pas compiler les paquets

    Important. Chaque build dépend du résultat des tests unitaires : si l'un échoue, le pipeline s'arrête.

    Astuce. Un commit qui contient [ignore] (de préférence dans sa description) saute toute la CI.

    2. ReleasesReleases

    TriggerResult
    tag vX.Y.Zstable packages and the GitHub release
    tag vX.Y.Z-<suffix> (ex: v4.3.1-pre)-pre packages (the 5 last versions of each are kept) and a GitHub pre-release
    a commit with [build]-pre packages
    a commit with [release], or any package build, once the unit tests passednotification of docker-image

    Every release is kept in the repositories; a -pre package is replaced by any release of the same version or higher. The notes of a GitHub release come from the CHANGELOG.md: its text can be rewritten afterwards (gh release edit).

    DéclencheurRésultat
    tag vX.Y.Zpaquets stables et la release GitHub
    tag vX.Y.Z-<suffix> (ex : v4.3.1-pre)paquets -pre (les 5 dernières versions de chacun sont gardées) et une pré-version GitHub
    un commit avec [build]paquets -pre
    un commit avec [release], ou tout build de paquets, une fois les tests unitaires passésnotification de docker-image

    Chaque release est gardée dans les dépôts ; un paquet -pre est remplacé par toute release de la même version ou d'une version supérieure. Les notes d'une release GitHub viennent du CHANGELOG.md : son texte peut être réécrit ensuite (gh release edit).

    3. PublicationPublication

    The packages are signed (GPG) and published on the gh-pages branch (https://tsukini22.github.io/libutils): fedora/44/x86_64 (RPM, createrepo_c), debian (APT stable main) and arch/x86_64 (pacman, repo-add: packages and database signed). Two publications never run at the same time (queued), and a push refused because gh-pages moved meanwhile is rebased and retried (5 times). The same branch serves this documentation in docs/ (copied by Docs - Pages (CD)).

    Les paquets sont signés (GPG) et publiés sur la branche gh-pages (https://tsukini22.github.io/libutils) : fedora/44/x86_64 (RPM, createrepo_c), debian (APT stable main) et arch/x86_64 (pacman, repo-add : paquets et base de données signés). Deux publications ne tournent jamais en même temps (mises en file d'attente), et un push refusé parce que gh-pages a bougé entre-temps est rebasé et relancé (5 fois). La même branche sert cette documentation dans docs/ (copiée par Docs - Pages (CD)).

    4. DownstreamEn aval

    After the packages are published, Dispatch (CI/CD) notifies the docker-image repository (repository_dispatch libutils-released) to rebuild the ci and mingw64-ci images with the new packages: on every package build, or on a commit containing [release], only once the unit tests passed.

    Une fois les paquets publiés, Dispatch (CI/CD) notifie le dépôt docker-image (repository_dispatch libutils-released) pour reconstruire les images ci et mingw64-ci avec les nouveaux paquets : à chaque build de paquets, ou sur un commit qui contient [release], seulement une fois les tests unitaires passés.

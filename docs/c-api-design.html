    The C API designConception de l'API C

    How the C API is built over the C++ classes: the guard, the handles and their common base, the callbacks, the strings, the fixed types of the templates, and what is not exposed.Comment l'API C est construite sur les classes C++ : la garde, les handles et leur base commune, les callbacks, les chaînes, les types fixes des templates, et ce qui n'est pas exposé.

    Updated 2026-11-26

    The C API is a thin layer over the C++ classes, written in C++: each section has a C header (CApi.h), a C++ header for its handles and its macros (CApi.hpp) and the functions (src/utils/<section>/CApi.cpp). This page explains its rules, for a reader of the code or a contributor; the user guide is Use libutils from C.

    L'API C est une fine couche sur les classes C++, écrite en C++ : chaque section a un header C (CApi.h), un header C++ pour ses handles et ses macros (CApi.hpp) et les fonctions (src/utils/<section>/CApi.cpp). Cette page explique ses règles, pour un lecteur du code ou un contributeur ; le guide utilisateur est Utiliser libutils depuis C.

    1. The guardLa garde

    utils/exception/CApi.hpp gives the tools every C function uses (namespace utils::exception::c_api):

    ToolRole
    guard(f)Runs f, catches everything, fills utils_exception on failure; returns UTILS_OK / UTILS_KO
    guard_fallback(fallback, f)Returns the result of f, or fallback when it threw (NULL, 0, false...)
    not_null(ptr, name) / not_null_ref(ptr, name)A NULL from the C side becomes InvalidArgument "The <name> is NULL", located at the caller
    set_status(e) / clear_status()Fill / reset the status of the thread
    _cold uint8_t utils_cli_get_code(const utils_cli_t* cli)
{
    return utils::exception::c_api::guard_fallback(0, [&](void) -> uint8_t {return utils::exception::c_api::not_null_ref(cli, "cli handle").cli.getCode();});
}

    On success only utils_exception.exception = false is written: the strings of an old failure stay, and the fast path copies nothing. The status is thread_local (_thread_local), like errno.

    utils/exception/CApi.hpp donne les outils utilisés par chaque fonction C (namespace utils::exception::c_api) :

    OutilRôle
    guard(f)Lance f, attrape tout, remplit utils_exception en cas d'échec ; renvoie UTILS_OK / UTILS_KO
    guard_fallback(fallback, f)Renvoie le résultat de f, ou fallback quand elle a levé une exception (NULL, 0, false...)
    not_null(ptr, name) / not_null_ref(ptr, name)Un NULL venu du côté C devient InvalidArgument "The <name> is NULL", situé chez l'appelant
    set_status(e) / clear_status()Remplit / réinitialise le statut du thread
    _cold uint8_t utils_cli_get_code(const utils_cli_t* cli)
{
    return utils::exception::c_api::guard_fallback(0, [&](void) -> uint8_t {return utils::exception::c_api::not_null_ref(cli, "cli handle").cli.getCode();});
}

    En cas de succès, seul utils_exception.exception = false est écrit : les chaînes d'un ancien échec restent, et le chemin rapide ne copie rien. Le statut est thread_local (_thread_local), comme errno.

    2. HandlesHandles

    A handle is a C++ struct declared opaque to C (typedef struct utils_cli utils_cli_t;) that holds the object (utils_cli { utils::cli::Cli cli; ... }). Every handle derives utils_handle, as its first base:

    MemberRole
    magicC_API_HANDLE_MAGIC while the handle lives, 0 once destroyed
    virtual destructorgives the handle a type known at runtime (RTTI)

    handle_base<T>(void* handle, name) reaches a base shared by many classes from any handle: it checks the magic ("The pointer is not a handle of the C API"), then dynamic_casts to T ("This handle has no <name>"). The generic C functions are built on it: utils_freezable_* (utils::type::Freezable) and utils_worker_* (utils::type::Worker) accept the handle of any class that derives them.

    utils_<name>_destroy(NULL) does nothing (like free). A handle that keeps a thread (the cli with THREAD) joins it in its destroy.

    Un handle est une struct C++ déclarée opaque pour C (typedef struct utils_cli utils_cli_t;) qui contient l'objet (utils_cli { utils::cli::Cli cli; ... }). Chaque handle dérive de utils_handle, comme première base :

    MembreRôle
    magicC_API_HANDLE_MAGIC tant que le handle vit, 0 une fois détruit
    destructeur virtueldonne au handle un type connu à l'exécution (RTTI)

    handle_base<T>(void* handle, name) atteint une base partagée par plusieurs classes depuis n'importe quel handle : il vérifie le magic ("The pointer is not a handle of the C API"), puis fait un dynamic_cast vers T ("This handle has no <name>"). Les fonctions C génériques sont construites dessus : utils_freezable_* (utils::type::Freezable) et utils_worker_* (utils::type::Worker) acceptent le handle de n'importe quelle classe qui en dérive.

    utils_<name>_destroy(NULL) ne fait rien (comme free). Un handle qui garde un thread (la cli avec THREAD) le joint dans son destroy.

    3. CallbacksCallbacks

    A C callback is a function pointer and a void* data, wrapped in a std::function on the C++ side. Around each call:

    1. reset_status() clears the error flag, so the status only holds the error of the callback;
    2. the callback runs and returns an int;
    3. check_callback(ret): anything other than UTILS_OK throws, with the info given by utils_fail (or "C callback failed (no info given with utils_fail)").

    The exception then goes up the C++ code like any other (a hook error of the cli, MiddlewareCall of a middleware, the message of an argument check) and ends in the status of the C call that ran it.

    Un callback C est un pointeur de fonction et un void* data, enveloppés dans une std::function côté C++. Autour de chaque appel :

    1. reset_status() efface le flag d'erreur, pour que le statut ne contienne que l'erreur du callback ;
    2. le callback tourne et renvoie un int ;
    3. check_callback(ret) : tout autre chose que UTILS_OK lève une exception, avec l'info donnée par utils_fail (ou "C callback failed (no info given with utils_fail)").

    L'exception remonte ensuite le code C++ comme n'importe quelle autre (une erreur de hook de la cli, MiddlewareCall d'un middleware, le message d'une vérification d'argument) et finit dans le statut de l'appel C qui l'a lancé.

    4. StringsChaînes

    utils/manip/smanip/CApi.hpp gives copy (into a fixed buffer, truncated) and copy_r (the _r convention: truncated, always '\0' terminated, returns the full length like snprintf), and bytes the bytes of a pointer + size of the C side in a std::string (NULL only with a size of 0). A function that builds a string has two forms: the plain one returns a thread_local std::string buffer of the function (valid until its next call in the thread), the _r one writes in a buffer of the caller. Bytes that can hold '\0' use a pointer + size, or a utils_string_t*.

    utils/manip/smanip/CApi.hpp donne copy (dans un buffer fixe, tronqué) et copy_r (la convention _r : tronqué, toujours terminé par '\0', renvoie la longueur complète comme snprintf), et bytes les octets d'un pointeur + une taille du côté C dans un std::string (NULL seulement avec une taille de 0). Une fonction qui construit une chaîne a deux formes : la forme simple renvoie un buffer thread_local std::string de la fonction (valide jusqu'à son prochain appel dans le thread), la forme _r écrit dans un buffer de l'appelant. Les octets qui peuvent contenir '\0' utilisent un pointeur + une taille, ou un utils_string_t*.

    5. Fixed typesTypes fixes

    C has no templates: a template is generated for a list of fixed types by X-macros of utils/type/CApiTypes.h, and has a generic version in bytes (data + size) for anything else.

    X-macroTypes (name: C type)
    C_API_INT_TYPESi8, i16, i32, i64 (int8_t ... int64_t), u8, u16, u32, u64, size (size_t)
    C_API_FLOAT_TYPESf32 (float), f64 (double), f128 (long double)
    C_API_NUMERIC_TYPESthe integers + the floating points
    C_API_VALUE_TYPESthe numeric types + bool, char
    C_API_TYPESthe value types + str (const char*, copied in a std::string)

    Each section unrolls the list it needs: C_API_NUMERIC_TYPES(C_API_CLUSTER_DECL) declares utils_cluster_i8_* ... utils_cluster_f128_*. Every macro is in a header and named C_API_*: the declarations (*_DECL) in the CApi.h, the handles (*_HANDLE) and the definitions (*_DEF, expanded in the CApi.cpp with its own helpers) in the CApi.hpp. On the C++ side, utils/type/CApiTypes.hpp gives Storage<C> and cpp_t<C>: how a C type is stored in C++ (const char* → std::string, the value types as they are) and converted back.

    TemplateGenerated for
    Cluster<T>numeric types (+ bytes)
    Middlewares<T, T>every type (+ void, bytes)
    Settings valuesevery type (+ the cast types, bytes)
    HybridMemory<T>value types (+ bytes)
    IdHandler<T>integers
    OVector2<T> / OVector3<T>numeric types (by value)
    OMatrix<T>numeric types (div / invert for the floating points)
    BidirectionalLookupTablestr_str, size_size, i64_i64, string ↔ each integer (both orders), bytes
    sos_embed / sos_extractu8, u16, u32, u64

    C n'a pas de templates : un template est généré pour une liste de types fixes par les X-macros de utils/type/CApiTypes.h, et a une version générique en octets (data + size) pour tout le reste.

    X-macroTypes (name : type C)
    C_API_INT_TYPESi8, i16, i32, i64 (int8_t ... int64_t), u8, u16, u32, u64, size (size_t)
    C_API_FLOAT_TYPESf32 (float), f64 (double), f128 (long double)
    C_API_NUMERIC_TYPESles entiers + les flottants
    C_API_VALUE_TYPESles types numériques + bool, char
    C_API_TYPESles types valeur + str (const char*, copié dans une std::string)

    Chaque section déroule la liste dont elle a besoin : C_API_NUMERIC_TYPES(C_API_CLUSTER_DECL) déclare utils_cluster_i8_* ... utils_cluster_f128_*. Chaque macro est dans un header et nommée C_API_* : les déclarations (*_DECL) dans le CApi.h, les handles (*_HANDLE) et les définitions (*_DEF, développées dans le CApi.cpp avec ses propres helpers) dans le CApi.hpp. Côté C++, utils/type/CApiTypes.hpp donne Storage<C> et cpp_t<C> : comment un type C est stocké en C++ (const char* → std::string, les types valeur tels quels) et reconverti.

    TemplateGénéré pour
    Cluster<T>types numériques (+ octets)
    Middlewares<T, T>tous les types (+ void, octets)
    Valeurs de Settingstous les types (+ les types de cast, octets)
    HybridMemory<T>types valeur (+ octets)
    IdHandler<T>entiers
    OVector2<T> / OVector3<T>types numériques (par valeur)
    OMatrix<T>types numériques (div / invert pour les flottants)
    BidirectionalLookupTablestr_str, size_size, i64_i64, chaîne ↔ chaque entier (dans les deux sens), octets
    sos_embed / sos_extractu8, u16, u32, u64

    7. Adding a C APIAjouter une API C

    For a new class of a section:

    1. include/utils/<section>/CApi.h: the opaque type, the enums / structs as C types (static_assert their values against the C++ ones in CApi.hpp), the prototypes with a comment saying the error value and the lifetime of what they return;
    2. include/utils/<section>/CApi.hpp: struct utils_<name>: public utils_handle { <Class> object; };, and for a fixed type its C_API_<NAME>_HANDLE / C_API_<NAME>_DEF macros;
    3. src/utils/<section>/CApi.cpp: each function in guard / guard_fallback, every pointer through not_null; add it to the SRC of the root CMakeLists.txt;
    4. the block of the section in include/utils/utils.h;
    5. the tests: tests/<section>/CApi.cpp (GoogleTest) and a function of tests/c/CApi.c (pure C, C11 and C23).

    Pour une nouvelle classe d'une section :

    1. include/utils/<section>/CApi.h : le type opaque, les enums / structs en types C (static_assert de leurs valeurs contre celles du C++ dans CApi.hpp), les prototypes avec un commentaire qui donne la valeur d'erreur et la durée de vie de ce qu'ils renvoient ;
    2. include/utils/<section>/CApi.hpp : struct utils_<name>: public utils_handle { <Class> object; };, et pour un type fixe ses macros C_API_<NAME>_HANDLE / C_API_<NAME>_DEF ;
    3. src/utils/<section>/CApi.cpp : chaque fonction dans guard / guard_fallback, chaque pointeur passé par not_null ; l'ajouter au SRC du CMakeLists.txt racine ;
    4. le bloc de la section dans include/utils/utils.h ;
    5. les tests : tests/<section>/CApi.cpp (GoogleTest) et une fonction de tests/c/CApi.c (C pur, C11 et C23).

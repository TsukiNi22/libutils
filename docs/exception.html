    ExceptionsExceptions

    Exceptions with a type and a code, their formatted output, every code of the library, and the status of the C API.Exceptions avec un type et un code, leur sortie formatée, tous les codes de la bibliothèque, et le statut de l'API C.

    Updated 2026-11-26
    DefineGroupNamespaceHeaders
    _Exception_Handlingutils::exceptionutils/exception/

    Every error of the library is reported by an exception carrying a type (how serious it is) and a code (what happened), never by a return code. To add the codes of your project, see Custom exception codes; the model is explained in Errors.

    DefineGroupeNamespaceHeaders
    _Exception_Handlingutils::exceptionutils/exception/

    Chaque erreur de la bibliothèque est signalée par une exception portant un type (sa gravité) et un code (ce qui s'est passé), jamais par un code de retour. Pour ajouter les codes de votre projet, voir Codes d'exception personnalisés ; le modèle est expliqué dans Erreurs.

    1. ClassesClasses

    ClassTypeDescription
    IException-Interface of every exception of the library (inherits std::exception)
    AException-Common implementation: code, type, info, source location, formatted output
    NoneExceptionNoneNot an error, more like an exit (ex: -h handled by ArgParser)
    WarningExceptionWarningSomething went wrong but the program can continue
    ErrorExceptionErrorError of the call
    CustomExceptiongivenException with the type given by the user (a Type combination)
    FatalExceptionFatalPrints the exception and ends the program with std::abort() from its constructor (no RAII cleanup)

    Every class has the constructors (code) and (code, info) for an InternalCode (library) or an ExternalCode (your project); the source location is taken automatically.

    Method (IException)ReturnsDescription
    what()const char*Message of the code (from the JSON config)
    info()const char*Info given at the construction, the default one of the code, or "[None]"
    getCode()InternalCodeCode of the exception (an external code is converted)
    getType()TypeType of the exception
    isNone() / isFatal()boolShortcut on the type
    loc()const std::source_location&Where the exception was built
    formated()std::stringFull colored output (see Output)

    utils::exception::format(type, file, line, module, what, function, info) builds the same output from its fields (used by formated() and by the C API).

    2. TypeType

    utils::exception::Type is a bit set, combined with |, &, ^, ~ (and their assignment versions):

    TypeValue
    None0b0001
    Fatal0b0010
    Error0b0100
    Warning0b1000

    Important. A code can restrict the types it accepts (column Restrictions of the codes). Building an exception with a forbidden type ends with a FatalException(ExceptionCodeRestriction).

    utils::exception::Type est un ensemble de bits, combinés avec |, &, ^, ~ (et leurs versions d'affectation) :

    TypeValeur
    None0b0001
    Fatal0b0010
    Error0b0100
    Warning0b1000

    Important. Un code peut restreindre les types qu'il accepte (colonne Restrictions des codes). Construire une exception avec un type interdit se termine par une FatalException(ExceptionCodeRestriction).

    3. Throw and catchLever et attraper

    #define _Exception
#include <utils/utils.hpp>

try {
    throw utils::exception::ErrorException(utils::exception::InternalCode::InvalidArgument, "the size must be > 0");
} catch (const utils::exception::IException& e) {
    if (e.getCode() == utils::exception::InternalCode::InvalidArgument)
        std::cerr << e.formated() << std::endl;
}

throw utils::exception::NoneException(utils::exception::InternalCode::Exit);                                // not an error
throw utils::exception::CustomException(utils::exception::Type::Error | utils::exception::Type::Warning, "info");
utils::exception::FatalException(utils::exception::InternalCode::Mmap, "shm");                              // prints & aborts

    Tip. Many functions of the library take a failsafe boolean: when it is true, the error is printed as a WarningException on std::cerr instead of being thrown.

    #define _Exception
#include <utils/utils.hpp>

try {
    throw utils::exception::ErrorException(utils::exception::InternalCode::InvalidArgument, "the size must be > 0");
} catch (const utils::exception::IException& e) {
    if (e.getCode() == utils::exception::InternalCode::InvalidArgument)
        std::cerr << e.formated() << std::endl;
}

throw utils::exception::NoneException(utils::exception::InternalCode::Exit);                                // not an error
throw utils::exception::CustomException(utils::exception::Type::Error | utils::exception::Type::Warning, "info");
utils::exception::FatalException(utils::exception::InternalCode::Mmap, "shm");                              // prints & aborts

    Astuce. Beaucoup de fonctions de la bibliothèque prennent un booléen failsafe : quand il vaut true, l'erreur est affichée comme une WarningException sur std::cerr au lieu d'être levée.

    5. In CEn C

    The C API never lets an exception cross the C boundary: each call is guarded, returns UTILS_OK / UTILS_KO (or NULL / 0) and, on failure, fills the thread local status utils_exception (read like errno). The full guide is Use libutils from C.

    C++C
    catch (const IException& e)if (ret != UTILS_OK) then read utils_exception
    e.getType() / e.getCode()utils_exception.type / utils_exception.code (C_API_OTHER_EXCEPTION_CODE for a non-libutils exception)
    e.what() / e.info()utils_exception.what / utils_exception.info
    e.loc()utils_exception.file, .line, .function, .module
    e.formated()utils_exception_format() / utils_exception_format_r(buf, size)
    throw ErrorException(code, info) in a callbackreturn utils_fail(code, info);

    utils_exception.exception is true when the last call failed; origin tells where the error comes from (C_API_EXCEPTION_ORIGIN_INTERNAL, _EXTERNAL, _STD, _UNKNOWN, _C).

    #define _Exception
#define _Verbose
#include <utils.h>
#include <stdio.h>

int main(void)
{
    if (utils_verbose_log(C_API_VERBOSE_BASIC, "%s", "hello") != UTILS_OK) {
        fprintf(stderr, "%s\n", utils_exception_format()); // same output as formated()
        return 1;
    }
    utils_fail(42, "set from C");                         // origin C_API_EXCEPTION_ORIGIN_C, returns UTILS_KO
    printf("%llu %s\n", (unsigned long long)utils_exception.code, utils_exception.info); // 42 set from C
    utils_exception_clear();
    return 0;
}

    L'API C ne laisse jamais une exception traverser la frontière C : chaque appel est protégé, renvoie UTILS_OK / UTILS_KO (ou NULL / 0) et, en cas d'échec, remplit le statut thread local utils_exception (lu comme errno). Le guide complet est Utiliser libutils depuis C.

    C++C
    catch (const IException& e)if (ret != UTILS_OK) puis lire utils_exception
    e.getType() / e.getCode()utils_exception.type / utils_exception.code (C_API_OTHER_EXCEPTION_CODE pour une exception qui ne vient pas de libutils)
    e.what() / e.info()utils_exception.what / utils_exception.info
    e.loc()utils_exception.file, .line, .function, .module
    e.formated()utils_exception_format() / utils_exception_format_r(buf, size)
    throw ErrorException(code, info) dans un callbackreturn utils_fail(code, info);

    utils_exception.exception vaut true quand le dernier appel a échoué ; origin indique d'où vient l'erreur (C_API_EXCEPTION_ORIGIN_INTERNAL, _EXTERNAL, _STD, _UNKNOWN, _C).

    #define _Exception
#define _Verbose
#include <utils.h>
#include <stdio.h>

int main(void)
{
    if (utils_verbose_log(C_API_VERBOSE_BASIC, "%s", "hello") != UTILS_OK) {
        fprintf(stderr, "%s\n", utils_exception_format()); // same output as formated()
        return 1;
    }
    utils_fail(42, "set from C");                         // origin C_API_EXCEPTION_ORIGIN_C, returns UTILS_KO
    printf("%llu %s\n", (unsigned long long)utils_exception.code, utils_exception.info); // 42 set from C
    utils_exception_clear();
    return 0;

    Interface for the cutomized exception handling

    // namespace utils::exception
class IException: public std::exception {
    virtual utils::exception::Type getType(void) const noexcept = 0;
    virtual utils::exception::InternalCode getCode(void) const noexcept = 0;
    virtual bool isNone(void) const noexcept = 0;
    virtual bool isFatal(void) const noexcept = 0;
    virtual const char* what(void) const noexcept = 0;
    virtual const char* info(void) const noexcept = 0;
    virtual const std::source_location& loc(void) const noexcept = 0;
    virtual std::string module(void) const noexcept = 0; // Module (shared library) that thrown it, empty -> the binary itself
    virtual std::string formated(void) const noexcept = 0;
    IException() = default;
    virtual ~IException() = default;
};

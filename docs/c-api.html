    Use libutils from CUtiliser libutils depuis C

    Call libutils from a C program: the root header utils.h, the link, the error status utils_exception, the handles, the strings and the callbacks.Appeler libutils depuis un programme C : le header racine utils.h, le link, le statut d'erreur utils_exception, les handles, les chaînes et les callbacks.

    Updated 2026-11-27

    Every section of libutils, except the compile time Concepts, can be called from C (C11 and C23 tested, C99 for the attributes): the same objects behind opaque handles, the same errors in a status read like errno. How it is built inside is on The C API design; each reference page has a section In C and the full C API of its section.

    Chaque section de libutils, sauf les Concepts de compilation, peut être appelée depuis C (C11 et C23 testés, C99 pour les attributs) : les mêmes objets derrière des handles opaques, les mêmes erreurs dans un statut qui se lit comme errno. Sa construction interne est sur Conception de l'API C ; chaque page de référence a une section En C et l'API C complète de sa section.

    1. SetupMise en place

    The C API is in the same library as the C++ one: libutils is C++, so the program is linked by a C++ linker (or with -lstdc++).

    project(app LANGUAGES C CXX)                             # CXX: the link of a C++ library
find_package(utils 5.0.0 REQUIRED)
add_executable(app main.c)
set_target_properties(app PROPERTIES LINKER_LANGUAGE CXX)
target_link_libraries(app PRIVATE utils::utils)          # includes, static library & OpenSSL
    gcc -std=c11 main.c -o app -lutils -lstdc++ -lssl -lcrypto -lm

    In strict C (-std=c11 / -std=c23) on Unix, the sections that use POSIX types (_Platform, _Encapsulation, _Network, _Cli...) need #define _POSIX_C_SOURCE 200809L before the first include; -std=gnu11 / gnu23 already have it.

    L'API C est dans la même bibliothèque que l'API C++ : libutils est en C++, donc le programme est lié par un linker C++ (ou avec -lstdc++).

    project(app LANGUAGES C CXX)                             # CXX: the link of a C++ library
find_package(utils 5.0.0 REQUIRED)
add_executable(app main.c)
set_target_properties(app PROPERTIES LINKER_LANGUAGE CXX)
target_link_libraries(app PRIVATE utils::utils)          # includes, static library & OpenSSL
    gcc -std=c11 main.c -o app -lutils -lstdc++ -lssl -lcrypto -lm

    En C strict (-std=c11 / -std=c23) sous Unix, les sections qui utilisent des types POSIX (_Platform, _Encapsulation, _Network, _Cli...) demandent #define _POSIX_C_SOURCE 200809L avant le premier include ; -std=gnu11 / gnu23 l'ont déjà.

    2. IncludeInclusion

    #define _Cli                 // the same section defines as utils.hpp (nothing defined = everything)
#include <utils.h>           // same as <utils/utils.h>

    utils.h takes the same defines as utils.hpp (_Utils, _Handling, _Tools, _Exception, _Cli, _Vector...) and _Warning / _NoWarning for the deprecation warnings. It checks with __has_include that the installed headers are there (C23, or the GCC / Clang extension) and gives the version (utils_version, __LIBUTILS_VERSION__). Like utils.hpp, it has no global guard: put the defines before every include.

    #define _Cli                 // the same section defines as utils.hpp (nothing defined = everything)
#include <utils.h>           // same as <utils/utils.h>

    utils.h prend les mêmes defines que utils.hpp (_Utils, _Handling, _Tools, _Exception, _Cli, _Vector...) et _Warning / _NoWarning pour les avertissements d'obsolescence. Il vérifie avec __has_include que les headers installés sont présents (C23, ou l'extension GCC / Clang) et donne la version (utils_version, __LIBUTILS_VERSION__). Comme utils.hpp, il n'a pas de garde globale : placez les defines avant chaque include.

    3. ErrorsErreurs

    No exception crosses the C boundary: each function runs in a guard that catches everything.

    The declarations carry _nothrow and _nodiscard: a result that is not read (status, handle, value) is a warning, (void)call(...) ignores it on purpose (not for utils_fail, utils_exception_set and the logs of the verbose). With gcc, the buffers (_read_only / _write_only), the strings (_null_terminated_string_arg) and the file descriptors of the platform (_fd_arg) are checked too.

    On failure the thread local status utils_exception holds the error; on success only utils_exception.exception is set back to false.

        return 0;                                        // not an error (ex: the code Exit)

    Aucune exception ne traverse la frontière C : chaque fonction tourne dans une garde qui attrape tout.

    Les déclarations portent _nothrow et _nodiscard : un résultat non lu (statut, handle, valeur) est un avertissement, (void)appel(...) l'ignore volontairement (pas pour utils_fail, utils_exception_set et les logs du verbose). Avec gcc, les tampons (_read_only / _write_only), les chaînes (_null_terminated_string_arg) et les descripteurs de fichier de la plateforme (_fd_arg) sont aussi vérifiés.

    4. HandlesHandles

    A class is an opaque handle: utils_<name>_t*, created by utils_<name>_create(...) (NULL on error) and released by utils_<name>_destroy(handle) (NULL does nothing). A function given a NULL handle fails with InvalidArgument.

    • A handle that holds another one documents it (utils_eetp_parser_set_codec takes the codec: never destroy it after); a result returned as a new handle is yours to destroy (utils_matrix_f64_invert, utils_hybrid_memory_get_gpu...).
    • The bases shared by many classes are reached on any handle: utils_freezable_*(void* handle), utils_worker_*(void* handle). A handle of another class fails with InvalidArgument ("This handle has no ...").
    • An object of a template is generated for the fixed types: utils_cluster_i32_t*, utils_matrix_f64_t*, utils_hybrid_memory_u8_t*..., plus a generic version in bytes (data + size).

    Une classe est un handle opaque : utils_<name>_t*, créé par utils_<name>_create(...) (NULL en cas d'erreur) et libéré par utils_<name>_destroy(handle) (NULL ne fait rien). Une fonction qui reçoit un handle NULL échoue avec InvalidArgument.

    • Un handle qui détient un autre handle le documente (utils_eetp_parser_set_codec prend le codec : ne le détruisez jamais ensuite) ; un résultat renvoyé comme nouveau handle est à vous de détruire (utils_matrix_f64_invert, utils_hybrid_memory_get_gpu...).
    • Les bases partagées par plusieurs classes s'atteignent depuis n'importe quel handle : utils_freezable_*(void* handle), utils_worker_*(void* handle). Un handle d'une autre classe échoue avec InvalidArgument ("This handle has no ...").
    • Un objet d'un template est généré pour les types fixes : utils_cluster_i32_t*, utils_matrix_f64_t*, utils_hybrid_memory_u8_t*..., plus une version générique en octets (data + size).

    6. CallbacksCallbacks

    Every callback takes a void* data given at its registration, and returns UTILS_OK on success. To fail, return UTILS_KO, or utils_fail(code, info) to give the message: the C++ side turns it into an exception with that info, and the call that ran the callback fails with it. Some callbacks have their own extra values: C_API_CLI_EXIT (stop the cli), C_API_CLI_NO_INPUT (getc hook).

    static int check_port(const char* option, void* data)
{
    long port = strtol(option, NULL, 10);

    (void)data;
    if (port < 1 || port > 65535)
        return utils_fail(1, "the port must be between 1 and 65535"); // the message of the parsing error
    return UTILS_OK;
}

    Chaque callback prend un void* data donné à son enregistrement, et renvoie UTILS_OK en cas de succès. Pour échouer, renvoyez UTILS_KO, ou utils_fail(code, info) pour donner le message : le côté C++ le transforme en exception avec cette info, et l'appel qui a lancé le callback échoue avec elle. Certains callbacks ont leurs propres valeurs supplémentaires : C_API_CLI_EXIT (arrête la cli), C_API_CLI_NO_INPUT (hook getc).

    static int check_port(const char* option, void* data)
{
    long port = strtol(option, NULL, 10);

    (void)data;
    if (port < 1 || port > 65535)
        return utils_fail(1, "the port must be between 1 and 65535"); // the message of the parsing error
    return UTILS_OK;
}

    7. ThreadsThreads

    utils_exception and the thread local buffers are per thread: read the status in the thread that made the call. The objects keep the thread safety of their C++ class (safe_mode arguments, the thread of a THREAD cli kept in its handle and joined with utils_cli_join).

    utils_exception et les buffers thread local sont propres à chaque thread : lisez le statut dans le thread qui a fait l'appel. Les objets gardent la thread safety de leur classe C++ (arguments safe_mode, le thread d'une cli THREAD gardé dans son handle et joint avec utils_cli_join).

    8. ExampleExemple

    #define _Verbose
#define _BLT
#include <utils.h>
#include <stdio.h>

int main(void)
{
    utils_blt_str_str_t* table = utils_blt_str_str_create();
    const char* other = NULL;

    if (!table)
        return 1;
    utils_verbose_set(C_API_VERBOSE_DEBUG);
    utils_blt_str_str_add(table, "fr", "France");
    if (utils_blt_str_str_get(table, "France", &other) == UTILS_OK)
        utils_verbose_log(C_API_VERBOSE_BASIC, "France -> %s", other);    // fr
    if (utils_blt_str_str_get(table, "de", &other) != UTILS_OK)             // unknown key
        utils_verbose_log(C_API_VERBOSE_DEBUG, "%s", utils_exception_format());
    utils_blt_str_str_destroy(table);
    return 0;
}

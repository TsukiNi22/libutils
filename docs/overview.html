    ArchitectureArchitecture

    What libutils is made of: one namespace, sections chosen with defines, a C++ API and a C API over the same objects, and the conventions shared by every class.De quoi est faite libutils : un seul namespace, des sections choisies avec des defines, une API C++ et une API C sur les mêmes objets, et les conventions partagées par toutes les classes.

    Updated 2026-11-26

    libutils is one static library (libutils.a, plus a debug and an asan build) for C++20 programs, with a C API over the same objects. Everything is in the namespace utils::; a program includes one root header and chooses the sections it needs.

    libutils est une seule bibliothèque statique (libutils.a, plus un build debug et un build asan) pour les programmes C++20, avec une API C sur les mêmes objets. Tout est dans le namespace utils:: ; un programme inclut un seul header racine et choisit les sections dont il a besoin.

    3. Two APIs, one libraryDeux API, une bibliothèque

    The C API is not a second implementation: each CApi.h declares C functions (extern "C") whose .cpp calls the C++ classes inside a guard. The objects are the same, so a C program gets the same behavior, the same threads and the same error codes. How the boundary works: The C API design.

    C++C
    Root header<utils/utils.hpp><utils/utils.h>
    An objecta class (utils::cli::Cli)an opaque handle (utils_cli_t*)
    An erroran exception (IException)UTILS_KO / NULL + the status utils_exception
    A templateCluster<T>one set of functions per fixed type (utils_cluster_i32_*) + a version in bytes
    A callbackstd::functiona function pointer + void* data

    4. ConventionsConventions

    • Every error is an exception (utils::exception::*Exception) with a code of Exception; catch const utils::exception::IException&. The model is on Errors.
    • Many methods take a failsafe boolean (print a warning instead of throwing) or a safe_mode boolean (lock, thread safe).
    • The check hooks return std::optional<std::string>: std::nullopt = valid, a string = the error message.
    • Most classes are movable but not copyable, and are tracked by an observer (memory leak report at exit).
    • Every class has the same API on Unix and Windows: only a call without Windows equivalent raises a FatalException (UndefinedCall).
    • The names follow one style: classes in PascalCase, methods in camelCase, tool functions in snake_case, members _camelCase, macros UPPER_CASE; the C API is utils_<section>_<name> and C_API_<SECTION>_<NAME>.
    • Chaque erreur est une exception (utils::exception::*Exception) avec un code de Exceptions ; attrapez const utils::exception::IException&. Le modèle est sur Erreurs.
    • Beaucoup de méthodes prennent un booléen failsafe (afficher un avertissement au lieu de lever une exception) ou un booléen safe_mode (verrou, thread safe).
    • Les hooks de vérification renvoient std::optional<std::string> : std::nullopt = valide, une chaîne = le message d'erreur.
    • La plupart des classes sont déplaçables mais pas copiables, et sont suivies par un observer (rapport des fuites mémoire à la sortie).
    • Chaque classe a la même API sous Unix et Windows : seul un appel sans équivalent Windows lève une FatalException (UndefinedCall).
    • Les noms suivent un seul style : classes en PascalCase, méthodes en camelCase, fonctions outils en snake_case, membres _camelCase, macros UPPER_CASE ; l'API C est utils_<section>_<name> et C_API_<SECTION>_<NAME>.

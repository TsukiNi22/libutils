    1. ClusterCluster

    MethodDescription
    spawn(args...)Build one element from the arguments (T must be constructible from them)
    spawn(std::size_t n, args...)Build n elements, each one from a copy of the arguments
    apply(std::function<void(T&)> fn)Call fn on every element, in the creation order
    size()Number of elements
    kill()Destroy every element
    kill(std::size_t n)Destroy the n last elements, ErrorException(OutOfBounds) if n > size()

    A Cluster can be moved, not copied.

    #define _Pool
#include <utils/utils.hpp>

utils::pool::Cluster<std::string> cluster;
cluster.spawn(std::size_t{3}, "worker");      // 3 x "worker"
cluster.spawn("leader");                       // 1 more
cluster.apply([](std::string& name) {name += "!";});
cluster.kill(1);                               // removes "leader!"
    MéthodeDescription
    spawn(args...)Construit un élément à partir des arguments (T doit être constructible à partir d'eux)
    spawn(std::size_t n, args...)Construit n éléments, chacun à partir d'une copie des arguments
    apply(std::function<void(T&)> fn)Appelle fn sur chaque élément, dans l'ordre de création
    size()Nombre d'éléments
    kill()Détruit chaque élément
    kill(std::size_t n)Détruit les n derniers éléments, ErrorException(OutOfBounds) si n > size()

    Un Cluster peut être déplacé, pas copié.

    #define _Pool

    2. MiddlewareMiddleware

    A Middlewares<T, U> stores two chains of functions: the before ones, called with a T, and the after ones, called with a U (void = no argument). The Cli uses them (cliMiddlewares, inputMiddlewares, promptMiddlewares...) to hook code around its actions.

    Typebefore called withafter called with
    Middlewares<T, U>TU
    Middlewares<T, void>Tnothing
    Middlewares<void, U>nothingU
    Middlewares<void, void>nothingnothing

    utils::pool::Middleware<T> is std::function<void(T)> (std::function<void(void)> for void).

    MethodDescription
    addBefore(middleware) / addBefore(std::vector<...>)Append one or several functions to the before chain
    addAfter(middleware) / addAfter(std::vector<...>)Append one or several functions to the after chain
    callBefore(arg) / callAfter(arg)Call the chain in the adding order (no argument for void)
    clear()Remove every middleware

    The chains are called on a snapshot, without the internal lock: a middleware can add / remove middlewares, the change applies to the next call.

    Warning. A middleware throwing a std::exception is reported as ErrorException(MiddlewareCall) with the original message as info.

    #define _Middleware
#include <utils/utils.hpp>

utils::pool::Middlewares<const std::string&, int> m;
m.addBefore([](const std::string& cmd) {std::cout << "> " << cmd << std::endl;});
m.addAfter([](int code) {std::cout << "exit code " << code << std::endl;});

m.callBefore("build");
m.callAfter(0);

    Un Middlewares<T, U> stocke deux chaînes de fonctions : celles before, appelées avec un T, et celles after, appelées avec un U (void = pas d'argument). Le Cli les utilise (cliMiddlewares, inputMiddlewares, promptMiddlewares...) pour accrocher du code autour de ses actions.

    Typebefore appelé avecafter appelé avec
    Middlewares<T, U>TU
    Middlewares<T, void>Trien
    Middlewares<void, U>rienU
    Middlewares<void, void>rienrien

    utils::pool::Middleware<T> est std::function<void(T)> (std::function<void(void)> pour void).

    MéthodeDescription
    addBefore(middleware) / addBefore(std::vector<...>)Ajoute une ou plusieurs fonctions à la chaîne before
    addAfter(middleware) / addAfter(std::vector<...>)Ajoute une ou plusieurs fonctions à la chaîne after
    callBefore(arg) / callAfter(arg)Appelle la chaîne dans l'ordre d'ajout (pas d'argument pour void)
    clear()Retire chaque middleware

    Les chaînes sont appelées sur un instantané, sans le verrou interne : un middleware peut ajouter / retirer des middlewares, le changement s'applique à l'appel suivant.

    Attention. Un middleware qui lève une std::exception est signalé comme ErrorException(MiddlewareCall) avec le message d'origine en info.

    #define _Middleware
#include <utils/utils.hpp>

utils::pool::Middlewares<const std::string&, int> m;
m.addBefore([](const std::string& cmd) {std::cout << "> " << cmd << std::endl;});
m.addAfter([](int code) {std::cout << "exit code " << code << std::endl;});

m.callBefore("build");
m.callAfter(0);

    3. In CEn C

    A template becomes one set of functions per fixed type (<name> = i8 ... u64, size, f32, f64, f128, see the fixed types), plus a generic version in bytes (data + size).

    C++C
    Cluster<T> (numeric T)utils_cluster_<name>_t*: utils_cluster_<name>_create, _spawn(cluster, n, value), _apply(cluster, fn, data), _kill, _kill_n, _size
    Cluster of any datautils_cluster_t* (bytes: utils_cluster_spawn(cluster, n, &value, sizeof(value)))
    Middlewares<void, void>utils_middlewares_t*
    Middlewares<T, T> (T a fixed type or str)utils_middlewares_<name>_t*
    Middlewares of any datautils_middlewares_bytes_t*

    The callbacks return UTILS_OK, or UTILS_KO / utils_fail(code, info) to stop the chain: the call then fails with MiddlewareCall and the info of the callback. Middlewares with a different type before and after are not generated.

    #define _Pool
#include <utils.h>
#include <stdio.h>

static int twice(int32_t* element, void* data)
{
    (void)data;
    *element *= 2;
    return UTILS_OK;
}

static int log_before(const char* cmd, void* data)
{
    (void)data;
    printf("> %s\n", cmd);
    return UTILS_OK;
}

int main(void)
{
    utils_cluster_i32_t* cluster = utils_cluster_i32_create();
    utils_middlewares_str_t* m = utils_middlewares_str_create();

    if (!cluster || !m)
        return 1;
    utils_cluster_i32_spawn(cluster, 3, 21);            // 3 x 21
    utils_cluster_i32_apply(cluster, twice, NULL);      // 3 x 42
    utils_middlewares_str_add_before(m, log_before, NULL);
    utils_middlewares_str_call_before(m, "build");      // "> build"
    printf("%zu elements\n", utils_cluster_i32_size(cluster));
    utils_middlewares_str_destroy(m);
    utils_cluster_i32_destroy(cluster);
    return 0;
}

    Un template devient un ensemble de fonctions par type fixe (<name> = i8 ... u64, size, f32, f64, f128, voir les types fixes), plus une version générique en octets (données + taille).

    C++C
    Cluster<T> (T numérique)utils_cluster_<name>_t* : utils_cluster_<name>_create, _spawn(cluster, n, value), _apply(cluster, fn, data), _kill, _kill_n, _size
    Cluster de données quelconquesutils_cluster_t* (octets : utils_cluster_spawn(cluster, n, &value, sizeof(value)))
    Middlewares<void, void>utils_middlewares_t*
    Middlewares<T, T> (T un type fixe ou str)utils_middlewares_<name>_t*
    Middlewares de données quelconquesutils_middlewares_bytes_t*

    Les callbacks renvoient UTILS_OK, ou UTILS_KO / utils_fail(code, info) pour arrêter la chaîne : l'appel échoue alors avec MiddlewareCall et l'info du callback. Les middlewares avec un type différent avant et après ne sont pas générés.

}

int main(void)
{

    if (!cluster || !m)

    typedef int (*utils_cluster_##name##_fn_t)(ctype* element, void* data); \
    _nodiscard _nothrow utils_cluster_##name##_t* utils_cluster_##name##_create(void); /* NULL on error */ \

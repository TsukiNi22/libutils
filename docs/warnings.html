    WarningsAvertissements

    Enable or disable the compile time warnings of libutils, all together, by domain or one by one.Activer ou désactiver les avertissements de compilation de libutils, tous ensemble, par domaine ou un par un.

    Updated 2026-11-26

    By default every warning of the library is disabled, except the forced ones (a missing header file, a fatal one). They are chosen with defines, before the include or for the whole project (add_definitions(-D_NoWarning)).

    Par défaut, tous les avertissements de la bibliothèque sont désactivés, sauf ceux qui sont forcés (un fichier header manquant, un avertissement fatal). Ils se choisissent avec des defines, avant l'include ou pour tout le projet (add_definitions(-D_NoWarning)).

    1. AllTous

    DefineEffect
    _WarningEvery warning
    _NoWarningNo warning

    Every define below has a disable version, NO_<define>. The names follow one pattern:

    domain warning (group):        <domain_name>_WARNING
esoteric warning (individual): <thing_name>_<domain_name>_WARNING
warning disable:               NO_<warning>
    DefineEffet
    _WarningTous les avertissements
    _NoWarningAucun avertissement

    Chaque define ci-dessous a une version de désactivation, NO_<define>. Les noms suivent un seul modèle :

    domain warning (group):        <domain_name>_WARNING
esoteric warning (individual): <thing_name>_<domain_name>_WARNING
warning disable:               NO_<warning>

    2. DomainsDomaines

    NameDefineWarns on
    DeprecatedDEPRECATED_WARNINGUse of something deprecated (only with the attribute _deprecated(info))
    Backward compatibilityBACKWARD_COMPATIBILITY_WARNINGUse of a renamed / old API kept for compatibility (_migration(x, y, z), _legacy)
    LinkerLINKER_WARNINGDependencies needed at the link, such as -lssl -lcrypto for the encryption
    UsageUSAGE_WARNINGThings to use carefully (promises needed for custom things...)
    NomDefineAvertit sur

    LinkerLINKER_WARNINGLes dépendances nécessaires au link, comme -lssl -lcrypto pour le chiffrement
    UsageUSAGE_WARNINGLes choses à utiliser avec précaution (promesses nécessaires pour les choses personnalisées...)

    4. AttributesAttributs

    The attributes of the declarations are checked by the compiler itself: these warnings don't depend on the defines above.

    AttributeWarns whenCompiler
    _nodiscard (every function of the C API that returns, except utils_fail, utils_exception_set and the logs)A status, a handle or a value is not read: (void)call(...) ignores it on purposegcc, clang
    _read_only / _write_only / _read_writeA buffer is smaller than the size given with itgcc
    _formatThe arguments don't match the format of a printf style loggcc, clang
    _warning(msg) / _error(msg)A function marked so is called (warning / error)gcc, clang
    _lifetimeboundA reference returned by a getter outlives its objectclang
    _fd_arg*, _null_terminated_string_argA closed descriptor or a string without '\0' is given (-fanalyzer)gcc 13+ / 14+

    Les attributs des déclarations sont vérifiés par le compilateur lui-même : ces avertissements ne dépendent pas des defines ci-dessus.

    5. ExampleExemple

    #define _Warning                            // everything
#define NO_BACKWARD_COMPATIBILITY_WARNING   // except the migration warnings
#include <utils/utils.hpp>

    In C, <utils.h> knows _Warning / _NoWarning for the deprecation warnings (DEPRECATED_WARNING, BACKWARD_COMPATIBILITY_WARNING).

    #define _Warning                            // everything
#define NO_BACKWARD_COMPATIBILITY_WARNING   // except the migration warnings
#include <utils/utils.hpp>

    En C, <utils.h> connaît _Warning / _NoWarning pour les avertissements d'obsolescence (DEPRECATED_WARNING, BACKWARD_COMPATIBILITY_WARNING).

libutils, a C++20 utility librarylibutils, une bibliothèque utilitaire C++20

Exceptions, verbose, CLI, arguments, TCP network, processes and shared memory, encryption, custom types and algorithms, in one static library distributed as RPM / DEB packages. The details of every class are in the wiki.Exceptions, verbose, CLI, arguments, réseau TCP, processus et mémoire partagée, chiffrement, types et algorithmes, dans une seule bibliothèque statique distribuée en paquets RPM / DEB. 1. Overview1. Vue d'ensemble

Everything is in the namespace utils::. A project includes only the root header <utils/utils.hpp> and chooses the sections it needs with defines placed before it; nothing defined means everything.Tout est dans le namespace utils::. Un projet inclut seulement l'en-tête racine <utils/utils.hpp> et choisit les sections voulues avec des defines placés avant ; sans define, tout est inclus.

The library linked follows the CMAKE_BUILD_TYPE of the project: Debug uses libutils_debug.a, Asan libutils_asan.a, anything else libutils.a; a missing package stops the configuration with the name of the package to install.La bibliothèque liée suit le CMAKE_BUILD_TYPE du projet : Debug utilise libutils_debug.a, Asan libutils_asan.a, le reste libutils.a ; un paquet manquant arrête la configuration en donnant le paquet à installer.

utils.hpp has no global guard: put the defines before every include of it, a bare include after a partial one only gets the sections already defined.utils.hpp n'a pas de garde globale : mettre les defines avant chaque include, un include nu après un include partiel n'obtient que les sections déjà définies.

4. Errors4. Erreurs

Every error is an exception carrying a type and a code, never a return code. The codes are generated at the build from cmake/config/exceptions/**/*.json; a project adds its own codes (ExternalCode) with the same JSON format.Chaque erreur est une exception portant un type et un code, jamais un code de retour. Les codes sont générés au build depuis cmake/config/exceptions/**/*.json ; un projet ajoute ses propres codes (ExternalCode) avec le même format JSON.

5. Network & EETP5. Réseau & EETP

A Server and a Client exchange payloads (strings ended by a separator, '\n' by default) through a socket object. listen() reads what is available without blocking, join() waits for the next epoll event; stop() / kill() can be called from another thread.Un Server et un Client échangent des payloads (chaînes terminées par un séparateur, '\n' par défaut) via un objet socket. listen() lit ce qui est disponible sans bloquer, join() attend le prochain événement epoll ; stop() / kill() peuvent être appelés depuis un autre thread.

5.1 EETP protocol5.1 Protocole EETP

EETPParser keeps the keys of each peer: the client sends SYN (its RSA public key, encrypted with the common RSA key of ~/.ssh/common), the server answers SO (a new AES-256 key, encrypted with the client key), then every message is AES-256-GCM encrypted with a new random iv.EETPParser garde les clés de chaque pair : le client envoie SYN (sa clé publique RSA, chiffrée avec la clé RSA commune de ~/.ssh/common), le serveur répond SO (une nouvelle clé AES-256, chiffrée avec la clé du client), puis chaque message est chiffré en AES-256-GCM avec un nouvel iv aléatoire.

6. Processes & IPC6. Processus & IPC

Process wraps fork / execvp / waitpid with pipes and fd duplications applied in the child; Poll wraps epoll; SharedObject loads a .so. SharedMemory passes messages between processes through a POSIX shared memory split in slots.Process encapsule fork / execvp / waitpid avec pipes et duplications de fd appliquées dans le fils ; Poll encapsule epoll ; SharedObject charge un .so. SharedMemory fait passer des messages entre processus via une mémoire partagée POSIX découpée en slots.

A message is addressed to one reader (Target(limit, ownership)) or to every reader (Target(limit), 0 = all the connected ones). An Id{id, ownership} links the answers of a conversation, join() waits for a message and returns when the memory is closed.Un message vise un lecteur (Target(limit, ownership)) ou tous (Target(limit), 0 = tous les connectés). Un Id{id, ownership} relie les réponses d'une conversation, join() attend un message et rend la main quand la mémoire est fermée.

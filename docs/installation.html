    InstallationInstallation

    Install libutils from the signed RPM / DEB / Arch packages, from the sources with CMake, or by copying the built library into your project.Installer libutils depuis les paquets RPM / DEB / Arch signés, depuis les sources avec CMake, ou en copiant la bibliothèque compilée dans votre projet.

    Updated 2026-11-26

    Three ways to install libutils: the packages of its own repository (recommended), the sources with CMake, or a copy of the built library in your project. Windows is on its own page.

    Trois façons d'installer libutils : les paquets de son propre dépôt (recommandé), les sources avec CMake, ou une copie de la bibliothèque compilée dans votre projet. Windows a sa propre page.

    2. PackagesPaquets

    setup.sh registers the package repository of libutils (https://tsukini22.github.io/libutils) in your package manager, then the packages install like any other:

    curl -fsSL https://raw.githubusercontent.com/TsukiNi22/libutils/main/setup.sh | bash -s   # or: wget -qO- <same url> | bash -s
sudo dnf install libutils       # Fedora / RHEL
sudo apt install libutils       # Debian / Ubuntu
sudo pacman -S libutils         # Arch Linux
    DistributionWhat setup.sh does
    rpmadds /etc/yum.repos.d/libutils.repo and imports the GPG key
    debadds the GPG key in /etc/apt/keyrings/libutils.gpg, the source in /etc/apt/sources.list.d/libutils.list, then apt-get update
    archadds the GPG key to the pacman keyring (pacman-key --add + --lsign-key), the [libutils] repository in /etc/pacman.conf (SigLevel = Required), then pacman -Sy
    ArgumentEffect
    --no-sudoRun without sudo (the script must already run as root)
    -h, --helpDisplay the usage
    PackageContent
    libutilsThe default packages: libutils-dev + libutils-op
    libutils-devEvery header and the global CMake configuration (requires openssl-devel / libssl-dev)
    libutils-dev-op / -dev-db / -dev-asCMake configuration of the optimized / debug / asan library
    libutils-opLibrary built with the optimization options (libutils.a)
    libutils-dbLibrary built with the debug options (libutils_debug.a, for debugging only)
    libutils-asLibrary built with AddressSanitizer (libutils_asan.a, for debugging only)

    Most packages have a pre-release version named <package>-pre, replaced by any release (without -pre) of the same version or higher. The same packages exist as RPM (Fedora), DEB (Debian / Ubuntu) and Arch Linux (.pkg.tar.zst, libraries in /usr/lib): same names, content and dependencies.

    Warning. An invalid hash error from dnf / apt: reset the cache of the tool or run setup.sh again. If it persists, the repository may be broken: open an issue.

    3. From the sourcesDepuis les sources

    Installed in /usr/local:

    git clone https://github.com/TsukiNi22/libutils.git && cd libutils
export BUILD_DIR=build
cmake -S . -B $BUILD_DIR
sudo cmake --build $BUILD_DIR --target install --parallel $(nproc)

    The build types and the targets (release, package_release) are on Build, tests and hooks.

    4. Copy in your projectCopie dans votre projet

    Build the library, then copy the headers and the archive where your project wants them:

    export BUILD_DIR=build
cmake -S . -B $BUILD_DIR -DCMAKE_BUILD_TYPE=Optimized
cmake --build $BUILD_DIR --parallel $(nproc)
cp -r include/* build/generated/* <your_project>/include/
cp build/libutils.a <your_project>/libs/

    Then compile with -I<your_project>/include/ -L<your_project>/libs/ -lutils -lssl -lcrypto, or in CMake:

    find_package(OpenSSL REQUIRED)
target_include_directories(${TARGET} PRIVATE include)
target_link_directories(${TARGET} PRIVATE ${CMAKE_SOURCE_DIR}/libs/)
target_link_libraries(${TARGET} PRIVATE utils OpenSSL::SSL OpenSSL::Crypto)

    Next: link it and choose the sections.

    Build, tests and hooksBuild, tests et hooks

    Build the three libraries and the packages, run the unit tests (C++ and pure C), and enable the xstyle pre-commit hook.Compiler les trois bibliothèques et les paquets, lancer les tests unitaires (C++ et C pur), et activer le hook pre-commit xstyle.

    Updated 2026-11-26

    For working on libutils itself: the build types and targets, the tests and the pre-commit hook. The CI that runs them is on CI / CD.

    Pour travailler sur libutils elle-même : les types de build et les cibles, les tests et le hook pre-commit. La CI qui les lance est sur CI / CD.

    2. Unit testsTests unitaires

    export BUILD_DIR=build
cmake -S . -B $BUILD_DIR -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTS=ON
cmake --build $BUILD_DIR --parallel $(nproc)
ctest --test-dir $BUILD_DIR --output-on-failure --timeout 30   # or ./unit_tests (written at the root)
    • GoogleTest, one file per module in tests/ (the C API of a section in tests/<section>/CApi.cpp).
    • tests/c/CApi.c is a pure C program built in C11 and C23 (c_api_c11, c_api_c23 in build/tests/), run by ctest (CApi.C11, CApi.C23).
    • The GPU libraries are loaded at runtime by HybridMemory: the backend tests are skipped without GPU.
    • In Asan mode (like the CI): the leaks made on purpose by the leak detection tests are suppressed (tests/lsan.supp), the GPU tests and HybridMemory.RamOverflow are skipped (the drivers are not instrumented, a failed operator new aborts instead of throwing).
    export BUILD_DIR=build
cmake -S . -B $BUILD_DIR -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTS=ON
cmake --build $BUILD_DIR --parallel $(nproc)
ctest --test-dir $BUILD_DIR --output-on-failure --timeout 30   # or ./unit_tests (written at the root)
    • GoogleTest, un fichier par module dans tests/ (l'API C d'une section dans tests/<section>/CApi.cpp).
    • tests/c/CApi.c est un programme en C pur compilé en C11 et C23 (c_api_c11, c_api_c23 dans build/tests/), lancé par ctest (CApi.C11, CApi.C23).
    • Les bibliothèques GPU sont chargées à l'exécution par HybridMemory : les tests des backends sont ignorés sans GPU.
    • En mode Asan (comme la CI) : les fuites volontaires des tests de détection de fuite sont supprimées (tests/lsan.supp), les tests GPU et HybridMemory.RamOverflow sont ignorés (les pilotes ne sont pas instrumentés, un operator new qui échoue avorte au lieu de lever une exception).

    3. Pre-commit hookHook pre-commit

    A shared xstyle hook (.githooks/pre-commit) checks the staged lines at each git commit: a minor (or worse) issue refuses the commit, anything else is only listed. The synced sources of sos and c2dmp-hsm are skipped.

    git config core.hooksPath .githooks   # once per clone
git commit --no-verify                # skip the hook once (or XSTYLE_HOOK=0 git commit ...)
xstyle --fix --staged                 # fix what can be, then git add -u

    Without xstyle installed the hook only warns and the commit is accepted. The thresholds are the variables at the top of .githooks/pre-commit.

    Un hook xstyle partagé (.githooks/pre-commit) vérifie les lignes indexées à chaque git commit : un problème minor (ou pire) refuse le commit, tout le reste est seulement listé. Les sources synchronisées de sos et c2dmp-hsm sont ignorées.

    git config core.hooksPath .githooks   # once per clone
git commit --no-verify                # skip the hook once (or XSTYLE_HOOK=0 git commit ...)
xstyle --fix --staged                 # fix what can be, then git add -u

    Sans xstyle installé, le hook avertit seulement et le commit est accepté. Les seuils sont les variables en haut de .githooks/pre-commit.

    4. DocumentationDocumentation

    This site is built from docs/site/ (Markdown pages, and generators reading the headers, the exception codes and the changelog) into docs/:

    docs/site/build.sh            # docs/*.html, search-index.js, site.css, site.js, sitemap.xml
docs/site/build.sh --check    # + links, accessibility, style and search checks

    The project graph (docs/graph.html) is generated separately. The GitHub wiki holds the same reference in Markdown, kept up to date with this site.

    Ce site est construit depuis docs/site/ (pages Markdown, et générateurs qui lisent les headers, les codes d'exception et le changelog) vers docs/ :

    docs/site/build.sh            # docs/*.html, search-index.js, site.css, site.js, sitemap.xml
docs/site/build.sh --check    # + links, accessibility, style and search checks

    Le graphe du projet (docs/graph.html) est généré à part. Le wiki GitHub contient la même référence en Markdown, tenue à jour avec ce site.

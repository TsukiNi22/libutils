    FAQFAQ

    Answers to the usual problems: install errors, a missing package at the configuration, the defines, Windows, OK / KO, and the C API.Les réponses aux problèmes courants : erreurs d'installation, un paquet manquant à la configuration, les defines, Windows, OK / KO, et l'API C.

    Updated 2026-11-26

    The problems met most often, with their answer.

    Les problèmes les plus fréquents, avec leur réponse.

    1. InstallInstallation

    dnf / apt says invalid hash. Reset the cache of the tool (dnf clean all, apt clean) or run setup.sh again; if it persists, the repository may be broken: open an issue.

    Which package for which build type? Debug needs libutils-db, Asan needs libutils-as, anything else libutils-op (in libutils). The configuration stops with the name of the missing package. See Link and include.

    What is a -pre package? The pre-release of the next version, built from main; any release of the same version or higher replaces it.

    dnf / apt affiche invalid hash ? Videz le cache de l'outil (dnf clean all, apt clean) ou relancez setup.sh ; si cela persiste, le dépôt est peut-être cassé : ouvrez une issue.

    Quel paquet pour quel type de build ? Debug demande libutils-db, Asan demande libutils-as, tout le reste libutils-op (dans libutils). La configuration s'arrête avec le nom du paquet manquant. Voir Lier et inclure.

    Qu'est-ce qu'un paquet -pre ? La pré-version de la prochaine version, compilée depuis main ; toute release de la même version ou d'une version supérieure la remplace.

    2. CompileCompilation

    A section I defined is missing. utils.hpp has no global guard: the defines must be placed before every include of it. A bare include after a partial one only gets the sections already defined. See Link and include.

    OK / KO clash with my own macros. libutils always defines UTILS_OK / UTILS_KO (used inside the library) and only defines OK / KO when they don't exist yet (_UTILS_OK_DEFINED / _UTILS_KO_DEFINED tell when it did); a warning is given when they exist with another value.

    A deprecation warning about _migration. The API is renamed and will be removed at the version given in the warning: move to the new name, or hide these warnings with NO_BACKWARD_COMPATIBILITY_WARNING (Warnings).

    Pourquoi une section que j'ai définie manque-t-elle ? utils.hpp n'a pas de garde globale : les defines doivent être placés avant chaque include de ce header. Un include nu après un include partiel n'obtient que les sections déjà définies. Voir Lier et inclure.

    OK / KO entrent-ils en conflit avec mes propres macros ? libutils définit toujours UTILS_OK / UTILS_KO (utilisées dans la bibliothèque) et ne définit OK / KO que s'ils n'existent pas encore (_UTILS_OK_DEFINED / _UTILS_KO_DEFINED indiquent quand elle l'a fait) ; un avertissement est émis quand ils existent avec une autre valeur.

    Pourquoi un avertissement d'obsolescence sur _migration ? L'API est renommée et sera supprimée à la version donnée dans l'avertissement : passez au nouveau nom, ou masquez ces avertissements avec NO_BACKWARD_COMPATIBILITY_WARNING (Avertissements).

    3. WindowsWindows

    Errors about _unused with <windows.h>. The complete <windows.h> declares a member named _unused, a macro of libutils: include <windows.h> before <utils/utils.hpp>, or define WIN32_LEAN_AND_MEAN.

    Process::spawn() aborts. Windows has no fork: use spawn(path, args) (CreateProcess). See Windows.

    No colors in the console. Call utils::iomanip::enable_ansi() (C: utils_iomanip_enable_ansi()) once at the start.

    Des erreurs sur _unused avec <windows.h> ? Le <windows.h> complet déclare un membre nommé _unused, une macro de libutils : incluez <windows.h> avant <utils/utils.hpp>, ou définissez WIN32_LEAN_AND_MEAN.

    Pourquoi Process::spawn() s'interrompt-il ? Windows n'a pas de fork : utilisez spawn(path, args) (CreateProcess). Voir Windows.

    Pas de couleurs dans la console ? Appelez utils::iomanip::enable_ansi() (C : utils_iomanip_enable_ansi()) une fois au démarrage.

    4. C APIAPI C

    Undefined references to std:: or operator new at the link. libutils is C++: link with a C++ linker (LINKER_LANGUAGE CXX in CMake) or add -lstdc++. See Use libutils from C.

    Unknown pid_t / struct sockaddr in strict C. Define _POSIX_C_SOURCE 200809L before the first include, or build with -std=gnu11 / gnu23.

    How do I know why a call failed? Read utils_exception in the same thread, or print utils_exception_format(). See Errors.

    My callback failed but the message is generic. Return utils_fail(code, "message") instead of UTILS_KO: the message becomes the info of the error.

    Can I pass any handle to utils_freezable_freeze? Yes, any handle of the C API: it fails with InvalidArgument when its class is not a Freezable.

    Des références indéfinies vers std:: ou operator new au link ? libutils est en C++ : liez avec un linker C++ (LINKER_LANGUAGE CXX en CMake) ou ajoutez -lstdc++. Voir Utiliser libutils depuis C.

    pid_t / struct sockaddr inconnus en C strict ? Définissez _POSIX_C_SOURCE 200809L avant le premier include, ou compilez avec -std=gnu11 / gnu23.

    Comment savoir pourquoi un appel a échoué ? Lisez utils_exception dans le même thread, ou affichez utils_exception_format(). Voir Erreurs.

    Pourquoi mon callback a-t-il échoué avec un message générique ? Renvoyez utils_fail(code, "message") au lieu de UTILS_KO : le message devient l'info de l'erreur.

    Puis-je passer n'importe quel handle à utils_freezable_freeze ? Oui, n'importe quel handle de l'API C : il échoue avec InvalidArgument quand sa classe n'est pas un Freezable.

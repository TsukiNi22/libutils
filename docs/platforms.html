    PlatformsPlateformes

    One code for Unix and Windows: the library only calls the system through utils::platform, POSIX on Unix, Win32 / Winsock / CRT on Windows, cross compiled with MinGW-w64.Un seul code pour Unix et Windows : la bibliothèque n'appelle le système qu'à travers utils::platform, POSIX sous Unix, Win32 / Winsock / CRT sous Windows, compilé en croisé avec MinGW-w64.

    Updated 2026-11-26

    Every class has the same API on Unix and Windows: the library only calls the system through utils::platform::, whose functions have the names, arguments and contract of POSIX (-1 and errno). On Unix they are the system calls, on Windows a Win32 / Winsock / CRT implementation. The same calls are given to the programs by the section Platform, in C++ and in C.

    Chaque classe a la même API sous Unix et Windows : la bibliothèque n'appelle le système qu'à travers utils::platform::, dont les fonctions ont les noms, les arguments et le contrat de POSIX (-1 et errno). Sous Unix, ce sont les appels système ; sous Windows, une implémentation Win32 / Winsock / CRT. Les mêmes appels sont fournis aux programmes par la section Platform, en C++ et en C.

    2. DifferencesDifférences

    No fork on Windows: Process::spawn() and a dup on a fd other than 0, 1, 2 raise a FatalException (UndefinedCall); spawn(path, args) uses CreateProcess.

    Other differences: Poll / Client / Server only handle sockets (at most 10 ms of latency), a Process has no signal, Ctrl+Z is a char for the Cli, a SharedMemory disappears with its last handle. Include <windows.h> before <utils/utils.hpp> (it declares a member named _unused, a libutils macro), or define WIN32_LEAN_AND_MEAN.

    Pas de fork sous Windows : Process::spawn() et un dup sur un fd autre que 0, 1, 2 lèvent une FatalException (UndefinedCall) ; spawn(path, args) utilise CreateProcess.

    Autres différences : Poll / Client / Server ne gèrent que des sockets (au plus 10 ms de latence), un Process n'a pas de signal, Ctrl+Z est un caractère pour la Cli, une SharedMemory disparaît avec son dernier handle. Incluez <windows.h> avant <utils/utils.hpp> (il déclare un membre nommé _unused, une macro de libutils), ou définissez WIN32_LEAN_AND_MEAN.

    3. Cross compilationCompilation croisée

    Windows binaries are built from Linux with MinGW-w64 and cmake/toolchain/mingw-w64.cmake, usable by any project. A project keeps the same CMake code for both platforms (find_package(utils) + utils::utils): only the configuration command adds the toolchain.

    Toolchain settingValue
    compilersx86_64-w64-mingw32-gcc / -g++ / -windres (-DMINGW_PREFIX=<triplet>)
    CMAKE_FIND_ROOT_PATHthe MinGW sysroot: /usr/x86_64-w64-mingw32/sys-root/mingw (Fedora), /usr/x86_64-w64-mingw32 (Debian); libraries, headers and packages searched only there
    CMAKE_CROSSCOMPILING_EMULATORwine when installed (WINEPATH = the sysroot bin/): ctest runs unit_tests.exe

    Build types: Debug uses mingw64-libutils-db, anything else mingw64-libutils-op; no Asan with MinGW. The complete guide is Windows.

    Les binaires Windows sont compilés depuis Linux avec MinGW-w64 et cmake/toolchain/mingw-w64.cmake, utilisable par n'importe quel projet. Un projet garde le même code CMake pour les deux plateformes (find_package(utils) + utils::utils) : seule la commande de configuration ajoute la toolchain.

    Réglage de la toolchainValeur
    compilateursx86_64-w64-mingw32-gcc / -g++ / -windres (-DMINGW_PREFIX=<triplet>)
    CMAKE_FIND_ROOT_PATHle sysroot MinGW : /usr/x86_64-w64-mingw32/sys-root/mingw (Fedora), /usr/x86_64-w64-mingw32 (Debian) ; bibliothèques, headers et paquets cherchés uniquement là
    CMAKE_CROSSCOMPILING_EMULATORwine quand il est installé (WINEPATH = le bin/ du sysroot) : ctest lance unit_tests.exe

    Types de build : Debug utilise mingw64-libutils-db, tout le reste mingw64-libutils-op ; pas d'Asan avec MinGW. Le guide complet est Windows.

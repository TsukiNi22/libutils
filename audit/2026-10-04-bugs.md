## 3. Sanitizer reports

| Report | Verdict | Reason |
|---|---|---|
| TSan: 2 data races in `SharedMemoryTest.ReadableLastOnly` (`send_` `SharedMemory.cpp:312,322` vs `read_` `:126,132`) | **false positive** | the test maps the same shared memory twice in one process (`server` and `client` instances, 2 `mmap`). TSan tracks the atomics by virtual address: the slot release done by the client's reader thread on **its** mapping (`reader` / `flag` atomics) is invisible from the server's mapping, so the chain reader `fetch_sub(release)` → releaser `acq_rel` → writer `acquire` isn't seen. Real users map it once per process. A clean TSan run is possible by running the client in a `fork`ed child |
| LSan: 24 leaks | false positive | intentional leaks of `tests/security/observer/{Observer,UnsafeObserver,MemoryLeakNotifer}.cpp` `DetectsLeak` (suppression `leak:*DetectsLeak*`) |

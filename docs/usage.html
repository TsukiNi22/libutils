    Link and includeLier et inclure

    Link libutils with CMake, include its root header and choose the sections you need with defines.Lier libutils avec CMake, inclure son header racine et choisir les sections nécessaires avec des defines.

    Updated 2026-11-26

    Once installed, a project links the CMake target utils::utils and includes one root header, with the sections it needs chosen by defines.

    Une fois installée, un projet lie la cible CMake utils::utils et inclut un seul header racine, avec les sections nécessaires choisies par des defines.

    1. CMakeCMake

    find_package(utils 5.0.0 REQUIRED)                       # minimal version
target_link_libraries(${TARGET} PRIVATE utils::utils)    # includes, static library & OpenSSL

    The library linked follows the CMAKE_BUILD_TYPE of your project:

    Your build typeLibraryPackage (Linux)Package (Windows)
    Debuglibutils_debug.alibutils-dbmingw64-libutils-db
    Asanlibutils_asan.a (build your project with -fsanitize=address too)libutils-asnone (no AddressSanitizer with MinGW, use Debug)
    anything elselibutils.a (optimized)libutils-op (in libutils)mingw64-libutils-op (in mingw64-libutils)

    A missing package stops the configuration with the name of the package to install (same names for RPM, DEB and Arch). The same CMake code works for Windows: see Windows.

    find_package(utils 5.0.0 REQUIRED)                       # minimal version
target_link_libraries(${TARGET} PRIVATE utils::utils)    # includes, static library & OpenSSL

    La bibliothèque liée suit le CMAKE_BUILD_TYPE de votre projet :

    Votre type de buildBibliothèquePaquet (Linux)Paquet (Windows)

    Un paquet manquant arrête la configuration avec le nom du paquet à installer (mêmes noms pour RPM, DEB et Arch). Le même code CMake fonctionne pour Windows : voir Windows.

    2. IncludeInclusion

    #define _Network        // only the needed sections (nothing defined = everything)
#include <utils/utils.hpp>

int main(void)
{
    std::cout << utils::version << std::endl; // "v5.0.0"
    return 0;
}

    #include <utils.hpp> is the same as <utils/utils.hpp> (a redirection, with a message when utils/utils.hpp can't be found). From C the root header is <utils.h>: see Use libutils from C.

    Important. Always include the root header, never a libutils header one by one. The only exception: the observers (<utils/security/observer/Observer.hpp>...).

    #define _Network        // only the needed sections (nothing defined = everything)
#include <utils/utils.hpp>

int main(void)
{
    std::cout << utils::version << std::endl; // "v5.0.0"
    return 0;
}

    #include <utils.hpp> équivaut à <utils/utils.hpp> (une redirection, avec un message quand utils/utils.hpp est introuvable). Depuis C, le header racine est <utils.h> : voir Utiliser libutils depuis C.

    Important. Incluez toujours le header racine, jamais un header de libutils un par un. La seule exception : les observers (<utils/security/observer/Observer.hpp>...).

    4. RulesRègles

    Warning. utils.hpp has no global include guard and the defines stay set for the rest of the file: put the defines before every include of utils.hpp (in a .hpp as in a .cpp). A bare include after a partial one only gets the sections already defined.

    Everything is in the namespace utils::. Most methods that can fail take a failsafe boolean (warn instead of throwing) or a safe_mode boolean (lock, thread safe); see Architecture.

    Attention. utils.hpp n'a pas de garde d'inclusion globale et les defines restent posés pour le reste du fichier : placez les defines avant chaque include de utils.hpp (dans un .hpp comme dans un .cpp). Un include nu après un include partiel n'obtient que les sections déjà définies.

    Tout est dans le namespace utils::. La plupart des méthodes qui peuvent échouer prennent un booléen failsafe (avertir au lieu de lever une exception) ou un booléen safe_mode (verrou, thread safe) ; voir Architecture.

    5. VersionVersion

    utils::version ("vX.Y.Z") and the macro __LIBUTILS_VERSION__ give the installed version ("[unknown]" when utils/version.hpp is missing). In C: utils_version and __LIBUTILS_VERSION__ from utils/version.h.

    utils::version ("vX.Y.Z") et la macro __LIBUTILS_VERSION__ donnent la version installée ("[unknown]" quand utils/version.hpp est absent). En C : utils_version et __LIBUTILS_VERSION__ depuis utils/version.h.

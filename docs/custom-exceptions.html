    Custom exception codesCodes d'exception personnalisés

    Add the exception codes of your project: a JSON config, the generator script, the CMake rule, then throw them as ExternalCode.Ajouter les codes d'exception de votre projet : une config JSON, le script générateur, la règle CMake, puis les lever en ExternalCode.

    Updated 2026-11-26

    The codes of libutils are internal (InternalCode); the ones of your project are external (ExternalCode). Both are written in JSON files and turned into a header by a Python script at the build. The classes and the codes of the library are on Exceptions.

    Important. An external code that duplicates an internal one only points to the internal one: its setup information is ignored.

    Tip. A project made from the cpp_project_template already has everything below. You can also install libutils from the sources with your codes added to its own JSON files: they become internal ones.

    Les codes de libutils sont internes (InternalCode) ; ceux de votre projet sont externes (ExternalCode). Les deux sont écrits dans des fichiers JSON et transformés en header par un script Python au build. Les classes et les codes de la bibliothèque sont sur Exceptions.

    Important. Un code externe qui duplique un code interne pointe seulement vers l'interne : ses informations de setup sont ignorées.

    Astuce. Un projet créé depuis le cpp_project_template a déjà tout ce qui suit. Vous pouvez aussi installer libutils depuis les sources avec vos codes ajoutés à ses propres fichiers JSON : ils deviennent des codes internes.

    1. JSON configConfig JSON

    Every .json under cmake/config/exceptions/ (recursively, any number of files) is read. Another folder works too: change const.py and the path of the CMake.

    {
    "errors": [
        {
            "code": "<code_name>",
            "message": "<error_message>",
            "info": "<sub_info>",
            "restrictions": ["<restriction1>", "<restriction2>"]
        }
    ]
}
    KeyUse
    codeThe name: utils::exception::ExternalCode::<code_name>
    messageReturned by what()
    infoReturned by info() when none is given (optional, "[None]" by default)
    restrictionsThe types the code accepts: None, Warning, Error, Fatal (optional, no restriction by default)

    The libutils config itself, for example:

    {
    "errors": [
        {
            "code": "ExceptionCodeRestriction",
            "message": "Error during the setup of an exception",
            "info": "Restriction trigerred on a code & type combination",
            "restrictions": ["Fatal", "Error"]
        },
        {"code": "Exit", "message": "Exit", "info": "Exit", "restrictions": ["None"]},
        {"code": "Empty", "message": "Empty"}
    ]
}

    Chaque .json sous cmake/config/exceptions/ (récursivement, autant de fichiers que voulu) est lu. Un autre dossier fonctionne aussi : modifiez const.py et le chemin du CMake.

    {
    "errors": [
        {
            "code": "<code_name>",
            "message": "<error_message>",
            "info": "<sub_info>",
            "restrictions": ["<restriction1>", "<restriction2>"]
        }
    ]
}
    CléUsage
    codeLe nom : utils::exception::ExternalCode::<code_name>
    messageRenvoyé par what()
    infoRenvoyé par info() quand aucune n'est donnée (optionnel, "[None]" par défaut)
    restrictionsLes types que le code accepte : None, Warning, Error, Fatal (optionnel, aucune restriction par défaut)

    La config de libutils elle-même, par exemple :

    {
    "errors": [
        {
            "code": "ExceptionCodeRestriction",
            "message": "Error during the setup of an exception",
            "info": "Restriction trigerred on a code & type combination",
            "restrictions": ["Fatal", "Error"]
        },
        {"code": "Exit", "message": "Exit", "info": "Exit", "restrictions": ["None"]},
        {"code": "Empty", "message": "Empty"}
    ]
}

    2. ScriptScript

    The scripts are in the project template, cmake/scripts/: copy the folder, or download only the useful files as scripts.zip and extract it at the root of the project.

    sha256sum scripts.zip
f969642ec52bb9bf0491ee215dae9b64f5e5775a574d87287fbd55146c4435b3  scripts.zip
    FileRole
    generate_exception_header.pyReads every .json of cmake/config/exceptions/ (recursively) and writes include/exception/generated_external_exception_header.hpp
    const.pyPaths (CONFIG_EXCEPTION, GENERATED_EXCEPTION_HEADER), the names of the generated sections (ExternalCode...) and the exception types
    requirements.txtPython packages to install before the generation (none for now: nothing is installed when the file is empty, nor when run as root)
    check_files.shOptional, used by the unregistered CMake target to list the src/*.cpp missing from the SRC list

    The generator stops with an error (and no header) on a code that isn't a C++ identifier, that is Undefined (reserved), or that is defined twice (in one or two files). A restrictions value other than None, Warning, Error, Fatal is reported and ignored.

    Les scripts sont dans le template de projet, cmake/scripts/ : copiez le dossier, ou téléchargez seulement les fichiers utiles dans scripts.zip et extrayez-le à la racine du projet.

    sha256sum scripts.zip
f969642ec52bb9bf0491ee215dae9b64f5e5775a574d87287fbd55146c4435b3  scripts.zip
    FichierRôle
    generate_exception_header.pyLit chaque .json de cmake/config/exceptions/ (récursivement) et écrit include/exception/generated_external_exception_header.hpp
    const.pyChemins (CONFIG_EXCEPTION, GENERATED_EXCEPTION_HEADER), noms des sections générées (ExternalCode...) et types d'exception
    requirements.txtPaquets Python à installer avant la génération (aucun pour l'instant : rien n'est installé quand le fichier est vide, ni quand il est lancé en root)
    check_files.shOptionnel, utilisé par la cible CMake unregistered pour lister les src/*.cpp absents de la liste SRC

    Le générateur s'arrête sur une erreur (et sans header) pour un code qui n'est pas un identifiant C++, qui vaut Undefined (réservé), ou qui est défini deux fois (dans un ou deux fichiers). Une valeur de restrictions autre que None, Warning, Error, Fatal est signalée et ignorée.

    3. CMakeCMake

    Run the script before the build, when the config changes:

    file(GLOB_RECURSE EXCEPTION_CONFIG_FILES
    CONFIGURE_DEPENDS
    "${CMAKE_SOURCE_DIR}/cmake/config/exceptions/*.json"
)
set(GENERATED_EXCEPTION_HEADER
    "${CMAKE_SOURCE_DIR}/include/exception/generated_external_exception_header.hpp"
)
add_custom_command(
    OUTPUT ${GENERATED_EXCEPTION_HEADER}
    COMMAND ${Python3_EXECUTABLE} ${CMAKE_SOURCE_DIR}/cmake/scripts/generate_exception_header.py
    WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
    DEPENDS ${EXCEPTION_CONFIG_FILES} ${CMAKE_SOURCE_DIR}/cmake/scripts/generate_exception_header.py
    COMMENT "Generating exception header (config changed)"
    VERBATIM
)
add_custom_target(generated_external_exception_header ALL # ALL: also generated for a header-only project
    DEPENDS ${GENERATED_EXCEPTION_HEADER}
)
add_dependencies(${TARGET} generated_external_exception_header)
target_include_directories(${TARGET} PRIVATE include/exception)   # where libutils finds your codes

    And link libutils as usual (find_package(utils 5.0.0 REQUIRED) + target_link_libraries(${TARGET} PRIVATE utils::utils)).

    4. UseUtilisation

    With an Exit code allowing the type None in your config:

    throw utils::exception::NoneException(utils::exception::InternalCode::Exit); // internal
throw utils::exception::NoneException(utils::exception::ExternalCode::Exit); // external

    Here both throw the same exception, the external Exit being a duplicate of the internal one. The output of formated():

    [Error(fatal)] .../src/utils/exception/AException.cpp:39 (utils) -> Error during the setup of an exception
-------------------------------------------
void utils::exception::AException::subinit(void) = Restriction trigerred on a code & type combination
-------------------------------------------

    In C, an external code is reported with utils_exception.origin == C_API_EXCEPTION_ORIGIN_EXTERNAL; a C function sets its own code with utils_fail(code, info) (see Use libutils from C).

    Avec un code Exit autorisant le type None dans votre config :

    throw utils::exception::NoneException(utils::exception::InternalCode::Exit); // internal
throw utils::exception::NoneException(utils::exception::ExternalCode::Exit); // external

    Ici, les deux lèvent la même exception, le Exit externe étant un doublon de l'interne. La sortie de formated() :

    [Error(fatal)] .../src/utils/exception/AException.cpp:39 (utils) -> Error during the setup of an exception
-------------------------------------------
void utils::exception::AException::subinit(void) = Restriction trigerred on a code & type combination
-------------------------------------------

    En C, un code externe est signalé avec utils_exception.origin == C_API_EXCEPTION_ORIGIN_EXTERNAL ; une fonction C pose son propre code avec utils_fail(code, info) (voir Utiliser libutils depuis C).
